# GuardCam — человек или животное, на слабом железе

Охрана дома и двора: камера реагирует на **людей**, а кошки, собаки, птицы,
тени, ветки и дождь не дёргают вас уведомлениями.

> **Статус: промежуточная версия (v0.1).** Пайплайн работает end-to-end, базовая
> модель обучена на COCO. Дальше — свои записи с камеры, ночной режим и QAT
> для полного int8. См. [дорожную карту](#дорожная-карта).

## Как устроено

```
кадр ──► детектор движения (OpenCV, ~0 вычислений)
            │ рамки, где что-то шевелится
            ▼
         вырезаем кусочки (кропы) ──► MobileNetV3-Small (1,8–5,8 МБ, ~3 мс/кроп на CPU)
                                          │ person / animal / background
                                          ▼
                              подтверждение по нескольким кадрам ──► снимок + Telegram
```

Нейросеть работает только когда есть движение и только на маленьких кусочках
кадра — поэтому всё влезает даже в Raspberry Pi или чип внутри камеры.

## Файлы

| Файл | Что делает |
|---|---|
| `common.py` | классы, препроцессинг, обёртка ONNX-модели |
| `motion.py` | детектор движения; умеет нарезать кропы из ваших записей |
| `build_coco_dataset.py` | стартовый датасет из COCO (качает только нужные картинки) |
| `train.py` | обучение с аугментациями «ночь/ИК» и «далёкий объект» |
| `export_onnx.py` | ONNX + квантование int8, сравнение размера/скорости/точности |
| `watch.py` | боевой режим: камера → тревога → Telegram |

## Быстрый старт (Windows, PowerShell)

Окружение лучше создавать по короткому пути (например, `C:\venvs\guardcam`):
из очень длинных путей Windows не может загрузить DLL PyTorch (ошибка WinError 206).

```powershell
python -m venv C:\venvs\guardcam
C:\venvs\guardcam\Scripts\activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt

# 1. Датасет (~250 МБ аннотаций + несколько ГБ трафика картинок, 20–60 минут)
python build_coco_dataset.py --out data --per-class 6000

# 2. Обучение (CPU, ~1,5 часа)
python train.py --data data --epochs 15

# 3. Экспорт и сжатие
python export_onnx.py --ckpt models/best.pt --data data

# 4. Запуск на вебкамере (0) или IP-камере (rtsp://...).
#    Готовые веса v1 уже лежат в models/ — шаги 1–3 можно пропустить.
python watch.py --source 0 --show
```

Telegram: создайте бота у @BotFather, затем

```powershell
$env:TELEGRAM_TOKEN = "..."; $env:TELEGRAM_CHAT_ID = "..."
python watch.py --source "rtsp://..."
```

## Результаты v1 (COCO, 15 эпох на CPU, ~1,5 часа)

Данные: 27 тыс. кропов train / 3 тыс. val из COCO train2017.

| Модель | Размер | Скорость (1 поток CPU) | Balanced acc |
|---|---|---|---|
| fp32 | 5,8 МБ | ~3 мс/кроп | 0,895 |
| веса int8 + активации int16 | 1,8 МБ | ~8 мс/кроп | 0,894 |
| полный int8 (не используется) | 1,8 МБ | ~3 мс/кроп | 0,46–0,63 |

Recall: человек 0,88, животное 0,90, фон 0,91. Не-человек ошибочно
назван человеком в ~5% кропов. Покадровое подтверждение в `watch.py`
(3 из 5 кадров) срезает большую часть таких одиночных ошибок.

Матрица ошибок (строки — истина, столбцы — предсказание; animal / background / person):

```
[[ 660   45   28]
 [  42 1215   72]
 [  47   75  882]]
```

**Почему не полный int8.** MobileNetV3 плохо переносит обычную пост-квантизацию:
у выходов ReLU в ранних и SE-блоках огромные выбросы (SQNR 2–5 дБ), и 8 бит
на активации не хватает. Исправление — quantization-aware training (QAT);
это следующий шаг, если нужна полная int8-скорость на NPU.

## Дорожная карта

1. **Базовая модель на COCO** — скрипты выше, результаты v1.
2. **Свои данные (самое важное).** Запишите 1–2 недели с камеры, нарежьте кропы:
   `python motion.py --source запись.mp4 --save-crops data/own_unsorted`
   — и разложите вручную по `data/train/{person,animal,background}`. Особенно
   ценны ночные кадры и ложные срабатывания (тени, ветки, насекомые у объектива).
3. **Честная метрика.** Не «accuracy», а: сколько ложных тревог в сутки при
   том, что ≥ 95% проходов людей пойманы. Сделайте отдельный тест-набор только
   из своих записей и никогда на нём не обучайтесь.
4. **Ночь.** Сравните качество днём и ночью отдельно; при необходимости — отдельный
   порог или отдельная голова для ч/б кадров.
5. **Железо.** Перенос на Raspberry Pi 5 / Orange Pi 5 (Rockchip NPU, через RKNN-Toolkit)
   как «умная коробочка» рядом с любой IP-камерой.
6. **Звёздочка.** Запуск прямо в камере на чипе Rockchip RV1103/RV1106 (платы Luckfox Pico).

## Идеи для улучшений и экспериментов

- Сравнить классификатор кропов vs. детектор на весь кадр (YOLO-nano) по метрике «ложные тревоги/сутки» и по затратам CPU.
- Hard negative mining: всё, что модель ошибочно назвала человеком, — в `background` и дообучить.
- Трекинг объектов между кадрами (не классифицировать одно и то же 25 раз в секунду).
- Зоны интереса: тревога только если человек зашёл в заданную область (калитка, дверь).
